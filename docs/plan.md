# 模拟经营游戏学习计划（数据驱动 · 强类型 · 纯代码路线）

## 总结

用 Python 3 + Pygame 从零开发“咖啡店模拟经营”游戏，学习目标是同时训练**游戏设计**
与**软件工程**：数据驱动、类型明确、分层解耦、测试与静态检查全绿。预计 3～6 个月
（每周 10+ 小时）交付一个可玩、可存档、可验证的成品，并预留第二作（游戏开发公司模拟）
复用架构。

## 工程规范（与玩法同级的验收项）

- **数据驱动**：配方、价格、需求曲线、随机事件、升级项等全部放 `config/` 下的 JSON；
  代码内禁止硬编码游戏数值。加载时用自定义校验器检查字段类型与范围，配置错误启动即报错，
  而不是运行中崩溃。
- **类型明确**：全部变量、参数、返回值标注类型。领域模型用 `@dataclass(frozen=True)`
  定义；对外接口用 `Protocol` 定义；字典操作用 `TypedDict`。项目配置 mypy（严格模式）
  作为必过检查。
- **注释与文档**：每个模块写模块 docstring（说明职责与关键权衡），每个公开函数/类写
  docstring（参数、返回、抛出异常），只在逻辑非显然处写行内注释（解释“为什么”，
  不解释“是什么”）。中文注释。
- **分层与依赖方向**：`sim`（纯逻辑，零 Pygame 依赖）→ `ui`（渲染与输入）→
  `app`（装配与主循环）。`ui` 只能通过 action 数据调用 sim，禁止渲染层直接改游戏状态；
  sim 通过接口返回结果，不感知 UI。目录采用“按游戏分包、层内分层”：
  每个游戏在 `eblock/` 下独立子包（如 `eblock/tetris/`、`eblock/coffee/`），
  子包内部再按 sim / ui / app / save 分层，互不共享命名空间。
- **静态检查工具链**：ruff（lint + format 检查）、mypy --strict、pytest。三者在每次
  里程碑提交前必须全绿，作为学习阶段的“提交门槛”。

## 关键接口与模块

- `sim` 核心接口：`step(daily_actions: list[Action]) -> DayResult`、
  `to_state() -> GameState`、`from_state(GameState) -> None`；
  `Action`/`GameState`/`DayResult` 均为 `TypedDict` 或 `@dataclass(frozen=True)`，
  保证 UI 与逻辑的边界清晰、可序列化存档。
- `config`：JSON 文件 + schema 校验模块，加载结果为冻结数据类（如 `MenuConfig`、
  `EventConfig`），游戏运行时只读。
- `save`：`GameState` ↔ JSON 存档，往返必须一致（有测试保证）。
- `ui`：Pygame 渲染纯展示组件，接收 sim 状态生成面板；输入事件转换为 action 列表。

## 开发路径（每阶段以学习目标为主线）

- 阶段 0（1～2 周）Pygame 热身：俄罗斯方块热身游戏（开发文档见 docs/tetris-warmup.md，
  实施指南见 docs/tetris-implementation.md），掌握主循环/事件/输入与碰撞，同时建立
  项目骨架（src 布局、ruff/mypy/pytest 配置、提交门槛）。
- 阶段 1（1～2 周）控制台版核心循环：命令行跑通“进货→定价→营业→随机需求→每日结算→
  再来一天”；用 pytest 覆盖定价、需求、结算、破产判定；此阶段全部是强类型纯逻辑，
  便于静默检查。
- 阶段 2（3～5 周）GUI 完整版：Pygame 实现资金/库存/天数面板、进货与定价界面、每日
  结果弹窗、事件提示、胜负条件、存档读档；所有玩法数值来自配置，UI 只做展示与转发输入。
- 阶段 3（2～3 周）数值平衡与数据驱动打磨：写“自动挂机脚本”跑几十局，统计利润率/客流/
  升级时机，依据数据调配置而非改代码；新增配置项走“改 JSON → 校验器同步 → 跑模拟”的
  固定流程，体会数据驱动的收益。
- 阶段 4（可选）第二作“游戏开发公司模拟”：复用 sim/ui/config/save 架构，新增员工/
  项目/市场系统，检验架构扩展性。

## 测试与验收

- 单元测试：sim 层全接口覆盖（定价、需求生成、进货校验、结算、事件、存档往返、配置校验
  错误路径）。
- 静态检查：`ruff check`、`mypy --strict`、`pytest` 三项全绿为每个里程碑的硬性完成条件。
- 可玩性验收：全新玩家 15 分钟学会并完成一轮完整循环；三种以上策略（低价走量/高价精品/
  事件博弈）都能达成胜利；破产后可读档重试。
- 工程验收：sim 可脱离 Pygame 独立运行与测试；配置全部外置且校验通过；Git 按里程碑提交，
  每提交满足提交门槛。

## 假设

- 美术与音频用色块/占位素材，不做发布，以“本地可运行、测试全绿、架构清晰”为完成标准。
- 类型方案用标准库 `dataclasses` + `typing` 而非 pydantic，以加深对类型系统的理解；
  若后续存档结构复杂化再评估迁移。
- 文档与注释用中文；代码标识符用英文。
- 阶段 4 可选，第一作完整交付为硬目标。
